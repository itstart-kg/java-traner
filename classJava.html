01Что такое класс и объект

Класс — это шаблон (чертёж), который описывает, какие данные будут у объектов и что они умеют делать.

Объект (экземпляр класса) — конкретная «вещь», созданная по этому шаблону. У каждого объекта свои значения данных.

Класс = чертёж

Чертёж дома: «у дома есть адрес, этажи, цвет». Жить в чертеже нельзя.

Объект = дом

Конкретный дом по чертежу: ул. Ленина 5, 9 этажей, белый. По одному чертежу можно построить сколько угодно домов.
Зачем это нужноБез классов данные студента лежали бы в разных переменных (name1, age1, name2…) и функции работали бы с ними отдельно. Класс собирает данные и поведение в одно целое — так код проще читать, расширять и проверять.

02Из чего состоит класс

Основные части класса:

  • Поля (fields) — переменные внутри класса, хранят состояние объекта.
  • Конструкторы — специальные блоки, которые срабатывают при создании объекта.
  • Методы — функции внутри класса, описывают поведение.
Student.java
public class Student {
    // ===== Поля (состояние) =====
    String name;
    int age;
    double gpa;

    // ===== Конструктор =====
    Student(String name, int age) {
        this.name = name;
        this.age = age;
        this.gpa = 0.0;
    }

    // ===== Методы (поведение) =====
    void introduce() {
        System.out.println("Привет, я " + name + ", мне " + age);
    }

    void study(int hours) {
        gpa += hours * 0.01;
        System.out.println(name + " учился " + hours + " ч.");
    }
}
Правило файлаВ Java public-класс должен лежать в файле с таким же именем: public class Student → Student.java. Имена классов пишутся с большой буквы (PascalCase), поля и методы — с маленькой (camelCase).

Значения полей по умолчанию

Если поле не инициализировано, Java сама присваивает ему значение по умолчанию:

Тип поляЗначение по умолчанию
int, long, short, byte0
double, float0.0
booleanfalse
char'\u0000' (нулевой символ)
Любой объект (String, массивы, свои классы)null
ВажноЭто работает только для полей. Локальные переменные внутри методов значений по умолчанию не получают — без инициализации код не скомпилируется.

03Создание объекта и оператор new

Main.java
public class Main {
    public static void main(String[] args) {
        Student aziz = new Student("Азиз", 19);
        Student aigerim = new Student("Айгерим", 20);

        aziz.introduce();
        aigerim.introduce();

        aziz.study(5);
        System.out.println(aziz.name + " — GPA: " + aziz.gpa);
    }
}
Привет, я Азиз, мне 19 Привет, я Айгерим, мне 20 Азиз учился 5 ч. Азиз — GPA: 0.05

Разберём строку Student aziz = new Student("Азиз", 19);

04Ссылки и память: стек и куча

Переменная объектного типа хранит не сам объект, а ссылку на него. Сами объекты живут в куче (heap), а локальные переменные со ссылками — в стеке (stack).

Ссылки
Student a = new Student("Азиз", 19);
Student b = a;                        // копируется ССЫЛКА, не объект
Student c = new Student("Айгерим", 20);

b.age = 25;
System.out.println(a.age);   // 25 — потому что a и b это один объект

System.out.println(a == b);  // true  — одна и та же ссылка
System.out.println(a == c);  // false — разные объекты
25 true false

null

null означает «ссылка никуда не указывает». Вызов метода у null даёт ошибку NullPointerException во время выполнения.

NullPointerException
Student s = null;
s.introduce();   // NullPointerException
Сборщик мусораЕсли на объект в куче больше не указывает ни одна ссылка, он становится недостижимым, и сборщик мусора (Garbage Collector) когда-нибудь освободит его память. Вручную удалять объекты в Java не нужно.

05Конструкторы

Конструктор — специальный метод, который вызывается при new. Его задача — привести объект в корректное начальное состояние.

  • Имя совпадает с именем класса.
  • Нет возвращаемого типа (даже void).
  • Вызывается автоматически, один раз на объект.

Конструктор по умолчанию

Если вы не написали ни одного конструктора, компилятор сам добавит пустой конструктор без параметров. Как только вы написали хотя бы один свой — автоматический пропадает.

Конструктор по умолчанию
class Cat {
    String name;
}

Cat c = new Cat();   // OK — компилятор создал Cat() сам

class Dog {
    String name;
    Dog(String name) { this.name = name; }
}

Dog d = new Dog();   // ОШИБКА компиляции: Dog() больше не существует
Dog d2 = new Dog("Рекс"); // OK

Перегрузка конструкторов

Конструкторов может быть несколько — с разными параметрами. Java выберет нужный по количеству и типам аргументов.

Product.java
public class Product {
    String title;
    double price;
    int quantity;

    Product(String title, double price, int quantity) {
        this.title = title;
        this.price = price;
        this.quantity = quantity;
    }

    Product(String title, double price) {
        this(title, price, 1);        // вызов другого конструктора
    }

    Product(String title) {
        this(title, 0.0);
    }
}

Product a = new Product("Ноутбук", 55000, 2);
Product b = new Product("Мышь", 800);   // quantity = 1
Product c = new Product("Подарок");      // price = 0.0, quantity = 1
Цепочка через this(...)Вся логика инициализации пишется в одном «главном» конструкторе, остальные вызывают его через this(...). Так нет дублирования кода. Вызов this(...) или super(...) исторически обязан быть первой инструкцией конструктора; начиная с Java 25 перед ним разрешён код, который не обращается к создаваемому объекту.

06Ключевое слово this

this — ссылка на текущий объект, тот, у которого сейчас вызван метод или конструктор. Три основных применения:

1. Различить поле и параметр с одинаковым именем

this.поле
class Student {
    String name;

    Student(String name) {
        name = name;        // ОШИБКА логики: параметр присвоен сам себе, поле осталось null
        this.name = name;   // правильно: поле объекта = параметр
    }
}

2. Вызвать другой конструктор

this(...) — показано в разделе выше.

3. Передать текущий объект куда-то ещё или вернуть его

Цепочка вызовов
class Counter {
    int value;

    Counter add(int n) {
        value += n;
        return this;            // возвращаем сам объект
    }
}

Counter c = new Counter();
c.add(5).add(10).add(3);       // цепочка вызовов
System.out.println(c.value);   // 18
18

08Инкапсуляция: геттеры и сеттеры

Инкапсуляция — сокрытие внутреннего состояния объекта. Данные закрыты (private), а работа с ними идёт только через методы, которые проверяют корректность.

Проблема: открытые поля

Плохо
class Student {
    public int age;
}

Student s = new Student();
s.age = -500;   // никто не мешает записать мусор

Решение: private + методы с проверкой

Хорошо
public class Student {
    private String name;
    private int age;

    public Student(String name, int age) {
        setName(name);
        setAge(age);
    }

    // Геттер — чтение
    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    // Сеттер — запись с проверкой
    public void setName(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("Имя не может быть пустым");
        }
        this.name = name;
    }

    public void setAge(int age) {
        if (age < 0 || age > 120) {
            throw new IllegalArgumentException("Некорректный возраст: " + age);
        }
        this.age = age;
    }
}

Student s = new Student("Азиз", 19);
s.setAge(20);                    // OK
System.out.println(s.getAge());  // 20
s.setAge(-500);                  // IllegalArgumentException
// s.age = 5;                    // ошибка компиляции: age is private
Не обязательно делать сеттер для каждого поляЕсли поле не должно меняться после создания (например, номер счёта), оставьте только геттер. Это уже решение уровня дизайна: класс сам решает, что можно менять снаружи.

Соглашение по именам: getX() / setX(), для boolean — isX() (например, isActive()).

09Методы и их перегрузка

Сигнатура метода: модификатор тип_результата имя(параметры).

Методы
public class Calculator {

    public int add(int a, int b) {        // возвращает int
        return a + b;
    }

    public double add(double a, double b) {   // перегрузка: другие типы
        return a + b;
    }

    public int add(int a, int b, int c) {      // перегрузка: другое число параметров
        return a + b + c;
    }

    public void printResult(int x) {           // void — ничего не возвращает
        System.out.println("Результат: " + x);
    }
}

Calculator calc = new Calculator();
System.out.println(calc.add(2, 3));        // 5
System.out.println(calc.add(2.5, 1.5));    // 4.0
System.out.println(calc.add(1, 2, 3));     // 6
5 4.0 6
Перегрузка ≠ разный тип результатаДва метода, отличающиеся только возвращаемым типом, — ошибка компиляции. Отличаться должны параметры (количество, типы или их порядок).

Передача аргументов

В Java аргументы всегда передаются по значению. Для объектов «значение» — это копия ссылки. Поэтому метод может изменить содержимое объекта, но не может заменить сам объект у вызывающего кода.

Передача по значению
static void rename(Student s) {
    s.setName("Новое имя");          // меняет объект — видно снаружи
}

static void replace(Student s) {
    s = new Student("Другой", 30);   // меняет только локальную копию ссылки
}

Student st = new Student("Азиз", 19);
rename(st);
System.out.println(st.getName());   // Новое имя
replace(st);
System.out.println(st.getName());   // Новое имя (не "Другой")

10static: члены класса, а не объекта

Обычные поля принадлежат каждому объекту отдельно. Поле с static принадлежит классу — существует в одном экземпляре и общее для всех объектов.

User.java
public class User {
    private static int count = 0;   // общий счётчик на весь класс
    private final int id;
    private String login;

    public User(String login) {
        count++;
        this.id = count;
        this.login = login;
    }

    public static int getCount() {  // static-метод
        return count;
    }

    public int getId() { return id; }
}

User u1 = new User("aziz");
User u2 = new User("aigerim");
User u3 = new User("bektur");

System.out.println(User.getCount());  // 3 — вызывается через имя класса
System.out.println(u3.getId());       // 3
3 3

Частая ошибкаИз static-метода нельзя напрямую обратиться к обычным полям и методам — нет объекта, к которому они относятся. Именно поэтому из main нельзя просто вызвать нестатический метод своего класса без new.

Примеры static из стандартной библиотеки: Math.max(), Math.PI, Integer.parseInt(), и сам public static void main.

12toString, equals, hashCode

Все классы в Java неявно наследуются от Object и получают от него несколько методов. Три самых важных обычно переопределяют.

toString()

По умолчанию печатает что-то вроде Student@1b6d3586 — имя класса и хеш. Бесполезно для отладки.

toString
@Override
public String toString() {
    return "Student{name='" + name + "', age=" + age + "}";
}

System.out.println(new Student("Азиз", 19));
Student{name='Азиз', age=19}

println и конкатенация со строкой вызывают toString() автоматически.

equals() и ==

== для объектов сравнивает ссылки (тот же ли это объект). equals() по умолчанию делает то же самое, но его переопределяют, чтобы сравнивать по содержимому.

equals + hashCode
import java.util.Objects;

public class Student {
    private String name;
    private int age;

    // ... конструктор, геттеры

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                      // тот же объект
        if (o == null || getClass() != o.getClass()) return false;
        Student other = (Student) o;
        return age == other.age && Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}

Student a = new Student("Азиз", 19);
Student b = new Student("Азиз", 19);
System.out.println(a == b);       // false — разные объекты
System.out.println(a.equals(b));  // true  — одинаковое содержимое
ПравилоПереопределили equals — обязательно переопределите hashCode. Равные по equals объекты должны давать одинаковый hashCode, иначе HashMap и HashSet будут работать неправильно.
СтрокиИменно поэтому строки сравнивают через s1.equals(s2), а не через ==.

IntelliJ IDEA генерирует все три метода сама: Alt+Insert (на macOS Cmd+N) → toString() / equals() and hashCode().

13Наследование (кратко)

Класс может расширять другой класс через extends и получить его поля и методы. Подробно — в отдельном посте, здесь база, чтобы было понятно, как классы связаны между собой.

Наследование
public class Person {
    protected String name;

    public Person(String name) {
        this.name = name;
    }

    public void introduce() {
        System.out.println("Я " + name);
    }
}

public class Student extends Person {
    private String university;

    public Student(String name, String university) {
        super(name);                  // вызов конструктора родителя
        this.university = university;
    }

    @Override
    public void introduce() {         // переопределение метода
        super.introduce();            // вызов версии родителя
        System.out.println("Учусь в " + university);
    }
}

Person p = new Student("Азиз", "МУА");
p.introduce();
Я Азиз Учусь в МУА
  • extends — наследование. В Java у класса может быть только один родитель.
  • super(...) — вызов конструктора родителя.
  • @Override — аннотация: компилятор проверит, что метод действительно переопределяет родительский.
  • Переменная типа родителя может хранить объект наследника — это основа полиморфизма.

14Полный пример: BankAccount

Всё вместе: private-поля, конструктор, валидация, static-счётчик, константа, final-поле, toString.

BankAccount.java
public class BankAccount {
    // Константа класса
    public static final double MIN_DEPOSIT = 1.0;

    // Общий счётчик для генерации номеров
    private static int accountCounter = 1000;

    // Состояние объекта
    private final String accountNumber;   // не меняется после создания
    private final String owner;
    private double balance;
    private final int pin;

    // Конструктор
    public BankAccount(String owner, int pin, double initialBalance) {
        if (initialBalance < 0) {
            throw new IllegalArgumentException("Начальный баланс не может быть отрицательным");
        }
        accountCounter++;
        this.accountNumber = "KG-" + accountCounter;
        this.owner = owner;
        this.pin = pin;
        this.balance = initialBalance;
    }

    // Перегруженный конструктор — счёт с нулевым балансом
    public BankAccount(String owner, int pin) {
        this(owner, pin, 0.0);
    }

    // ===== Публичное поведение =====
    public boolean checkPin(int input) {
        return this.pin == input;
    }

    public void deposit(double amount) {
        if (amount < MIN_DEPOSIT) {
            System.out.println("Минимальное пополнение: " + MIN_DEPOSIT);
            return;
        }
        balance += amount;
        System.out.println("Пополнено: " + amount + ". Баланс: " + balance);
    }

    public boolean withdraw(double amount) {
        if (amount <= 0) {
            System.out.println("Сумма должна быть больше нуля");
            return false;
        }
        if (amount > balance) {
            System.out.println("Недостаточно средств. Баланс: " + balance);
            return false;
        }
        balance -= amount;
        System.out.println("Снято: " + amount + ". Баланс: " + balance);
        return true;
    }

    public boolean transferTo(BankAccount target, double amount) {
        if (target == null || target == this) {
            System.out.println("Некорректный получатель");
            return false;
        }
        if (withdraw(amount)) {
            target.balance += amount;   // private доступен внутри того же класса
            return true;
        }
        return false;
    }

    // ===== Геттеры (сеттера для balance нет намеренно) =====
    public double getBalance()       { return balance; }
    public String getAccountNumber() { return accountNumber; }
    public String getOwner()         { return owner; }

    @Override
    public String toString() {
        return accountNumber + " | " + owner + " | " + balance + " сом";
    }
}
Main.java
public class Main {
    public static void main(String[] args) {
        BankAccount aziz = new BankAccount("Азиз", 1234, 5000);
        BankAccount aigerim = new BankAccount("Айгерим", 4321);

        System.out.println(aziz);
        System.out.println(aigerim);

        aziz.deposit(1500);
        aziz.withdraw(10000);
        aziz.transferTo(aigerim, 2000);

        System.out.println(aziz);
        System.out.println(aigerim);
        System.out.println("PIN верный? " + aziz.checkPin(1234));
    }
}

Что здесь важно Баланс нельзя поменять напрямую — только через deposit, withdraw, transferTo, и каждый из них проверяет данные. Это и есть смысл класса: объект сам отвечает за то, чтобы его состояние всегда было корректным.
Для реальных денегdouble здесь для простоты. В настоящих финансовых расчётах используют BigDecimal или хранят сумму в целых тыйынах (long), потому что double даёт ошибки округления: 0.1 + 0.2 = 0.30000000000000004.

15Частые ошибки новичков

  • name = name; в конструкторе без this — поле остаётся null.
  • Вызов метода у null — объект объявлен, но не создан через new → NullPointerException.
  • Сравнение объектов через == вместо equals(), особенно строк.
  • Обращение к обычному полю из static main → ошибка «non-static variable cannot be referenced from a static context».
  • Ожидание конструктора по умолчанию, когда уже написан свой с параметрами.
  • Указание void у конструктора: public void Student() — это уже обычный метод, а не конструктор. Компилятор не ругается, но объект не инициализируется.
  • Все поля public — любой код может записать в объект некорректные данные.
  • equals без hashCode — объекты «теряются» в HashSet/HashMap.
  • Класс-«бог» — один класс делает всё (ввод, логику, вывод, хранение). Один класс — одна ответственность.

Проверь себя

1. Чем класс отличается от объекта?Класс — описание (шаблон), объект — конкретный экземпляр в памяти, созданный по этому описанию через new.
2. Когда компилятор создаёт конструктор по умолчанию?Только если в классе не объявлено ни одного конструктора.
3. Что выведет код: Student a = new Student("A",1); Student b = a; b.setAge(5); System.out.println(a.getAge());5. a и b ссылаются на один и тот же объект.
4. Почему из static-метода нельзя обратиться к обычному полю?Обычное поле принадлежит конкретному объекту, а static-метод вызывается без объекта — непонятно, чьё поле брать. this в static-контексте отсутствует.
5. Зачем делать поля private, если можно public?Чтобы объект сам контролировал своё состояние: проверял входные данные и не допускал некорректных значений. Также можно менять внутреннюю реализацию, не ломая код, который использует класс.
6. Что не так: public void Car(String model) { this.model = model; }Из-за void это обычный метод с именем Car, а не конструктор. При new Car("BMW") будет ошибка компиляции, если другого подходящего конструктора нет.
